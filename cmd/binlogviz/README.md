# Binlogviz Command Module

Cobra CLI entrypoints and command-layer orchestration for analyze, flashback, compare, trend, snapshot, version, schema, and workflow commands including run, resume, validate, describe, status, and clean.

## Files

| File | Responsibility |
|------|----------------|
| `root.go` | Builds the root command and registers `analyze`, `flashback`, `compare`, `trend`, `snapshot`, `version`, `workflow`, and `schema`. Group commands (root, `snapshot`, `workflow`) refuse an unknown subcommand as a usage error; `--error-format` takes only `text` or `json`; `--tz` selects the display zone (absent or `UTC` keeps the historical UTC spelling; a zoneless `--start`/`--end` is read in that zone when `--tz` is set, including `--tz UTC`; `Local` is exit 3); cobra prints no usage text or error itself, main prints the one error line (#268). |
| `flashback.go` | Prints undo SQL for selected ROW changes. Reuses analyze path resolution and selectors, reads optional `--schema-file` table definitions and `--schema-file-db`, translates flashback help, then returns before report rendering. `--sql-context off` refuses. `--help` describes that flag for flashback, not with analyze's query-text wording, and includes an example (#255). |
| `analyze.go` | Orchestrates explicit-path, stdin `-`, or discovery-mode analyze execution through one streaming path (optional injected normalize, optional HTML dest), explicit `--workload-id` persistence, `analyze --help` names per-transaction `server_id`, `thread_id`, GTID, `xid` or XA xid, and `user@host`, and `--diagnostics full|summary|off`, aggregate parse progress on `stderr`, Format Description server-version plumbing for replay commands, optional snapshot persistence (always full diagnostics), and command-owned DuckDB temp-store lifecycle. `report.Write` owns the format switch. An unknown `--format` is exit 3 before any input is read. A failed activity-spill read, while the analysis finishes or while rendering, is exit 11 (kind spill), not an output write failure. |
| `analyze_paths.go` | Resolves analyze input paths: explicit files, directory discovery with a shared binlog prefix inside a time window, or a server `--index-file` manifest read in listed order (a missing entry fails rather than dropping history), readability checks, and the file-coverage model a report claims. |
| `analyze_time.go` | Parses RFC3339 or local `YYYY-MM-DD HH:MM:SS` `--start`/`--end` flags: documents UTC binlog timestamps and explicit-offset RFC3339 filters, rejects an offset past 14:00 or minutes outside 00/30/45, and rejects a DST gap or overlap in the zoneless form. |
| `analyze_options.go` | Builds `analyzer.Options`, `report.Options`, and snapshot metadata from parsed flags and validates the flag combination. Snapshot `input_mode` is `remote` for a `--host` run. |
| `analyze_flags.go` | Registers the analyze flag surface, including the nine remote input flags (`--host`/`--port`/`--user`/`--password`/`--server-id`/`--start-file`/`--start-pos`/`--start-gtid`/`--ssl-mode`). |
| `analyze_remote.go` | Remote analyze input mode (ADR 0021): flag detection and mutual exclusion with positional/discovery/`--start-position` modes, flag-to-`remote.Config` validation (`--user` defaults to the OS login, `BINLOGVIZ_MYSQL_PASSWORD` fills `--password`, `--start-gtid` picks MySQL or MariaDB flavor from the set's format), connect through the replaceable `remoteOpenSource` seam, the `remote://host:port` synthetic input, manifest-derived file coverage and stream boundary, and `remote.Error` → `clierr` mapping (`start_pos` is usage; connect/TLS/auth/manifest/privilege/start_file/stream are input with `details.reason`). |
| `analyze_errors.go` | Maps analyze failures: parse-error wrapping and cause cleanup, localized operator errors, and the no-workload guards — Unclassified QUERY / open BEGIN / SAVEPOINT / Ignored-only exit 1 with one `Error:` line when that condition intersected the window, after-window Unclassified QUERY keeping the in-window report, and no-data exit 2 including ADMIN-only files. |
| `analyze_selection.go` | Validates single-file position selectors against exact parsed event boundaries and EOF before report rendering. |
| `analyze_output.go` | Resolves analyze HTML destination: explicit `--output`, `--output -`, TTY default cwd file, and non-TTY stdout redirect. |
| `exit.go` | Maps command errors onto process exit codes by kind (`internal/clierr`, ADR 0008, 0009 and 0012: 1 error, 2 no data, 3 usage, 4 input, 5 corrupt, 6 refused, 7 conflict, 8 output, 9 unsupported, 10 resource, 11 spill), prints one `Error:` line after clearing a progress line, or one JSON error line with `--error-format json`. |
| `terminal.go` | Terminal hygiene (#253): the progress bar and `\r\033[2K` only on an interactive stderr (a TTY, `TERM` not `dumb`, no `--quiet`). A pipe or file gets the one plain `Finalizing analysis...` line; `--quiet`/`-q` and JSON errors drop info lines too (#268). Errors and warnings always print. |
| `interrupt.go` | Removes stdin/pipe temp copies on SIGHUP (exit 129), SIGINT (exit 130), SIGQUIT (exit 131), and SIGTERM (exit 143) and prints `Error: interrupted`. Unix only for SIGHUP and SIGQUIT. |
| `analyze_stdin.go` | Spools non-seekable stdin, pipes, and fifos. A real TTY is a terminal error. `/dev/null` and an empty pipe say `stdin has no data`. Replay aliases the spool to `stdin` without inventing a cwd path. |
| `analyze_parallel.go` | Runs bounded parallel per-file parsing while preserving ordered analyzer consumption for cross-file transaction safety. |
| `compare.go` | Resolves compare inputs from explicit JSON files or named snapshots and renders text/JSON/HTML compare output with actionable invalid-input errors; a report file that cannot be read is an input error, exit 4 (#268). `compareFormats` is the authoritative --format list and the render switch has no default arm — an unhandled listed format errors instead of falling back to text. |
| `trend.go` | Resolves explicit or pattern-selected snapshot inputs, optional baseline snapshots, and renders text/JSON/HTML multi-snapshot trend output. `trendFormats` is the authoritative --format list with the same no-default render switch as compare. |
| `snapshot.go` | Implements `snapshot save`, `snapshot list`, `snapshot show`, `snapshot rename`, and `snapshot delete`, including machine-readable list/show output. List adds a diagnostics column for a reduced document, and prints `(empty)` for `diagnostics_mode` `""` (#308, #312). Save rewrites only timestamp-keyed fields (`timestamp`, `minute`, `*_time`, `*_at`, `*_minute`) to UTC; an RFC3339-looking `workload_id` keeps its spelling. |
| `version.go` | Prints logo, version and, when Go embedded it, the commit; `--format json` prints `schema_version`, `version`, `commit`, `commit_time`, `modified`, `go_version` (ADR 0010). |
| `json_versions.go` | The `schema_version` of each command-level JSON output (snapshot, workflow, version), written through `internal/jsonout` (ADR 0010). |
| `schema.go` | `binlogviz schema` lists the versioned JSON outputs and `binlogviz schema <name>` prints the derived JSON Schema. The catalog is `schemaOutputs()`, shared with the version and schema tests (ADR 0017). `workflow-describe` is a oneOf of the success preview and the failure object `workflow validate` already prints. |
| `workflow.go` | Implements `workflow run <plan.yaml>`, `workflow resume <output_dir>`, canonical rooted plan references, pre-run `workflow validate <plan.yaml>` checks, static `workflow describe <plan.yaml>` previews, read-only `workflow status <output_dir>` inspection, dry-run-first `workflow clean <output_dir>` cleanup, and `workflow export <output_dir>` with `--output`/`-o`. |
| `workflow_output.go` | Renders validate/describe/status/clean results in text or JSON and the export summary payload. |
| `workflow_exec.go` | Executes a workflow plan: resume with rerun selectors, per-window analyze/compare/trend steps, the manifest, and the index page. |
| `*_test.go` | Covers every command `--help` example and a non-interactive stdin guard, UTC/explicit-offset analyze help, local `YYYY-MM-DD HH:MM:SS` time parsing, flag parsing, inclusive-window adjacent-file planning, intersected time/position selection, GTID group filtering including zero-row XA COMMIT selection, report-v3 round trips, MySQL/MariaDB provenance and real `XAPrepareLogEvent`/LOAD_DATA SQL-context compatibility, snapshots, analyze/compare integration, Unclassified QUERY / Ignored QUERY / ADMIN-only command I/O including anonymous empty-identity next-GTID and finalize, after-window Unclassified QUERY exit 0 with the in-window report, plain ROLLBACK and XA END then a different GTID exit 0, real-parser exit 0 on the MySQL 8.0.46 `FLUSH TABLES`, `CHECK TABLE`, and `SET ROLE` dialect fixtures, real-parser index DDL on mysql-8.0.46-index-ddl.binlog attributed to the table after `ON` including under `--include-table`, real-parser exit 1 on the MySQL 8.0.46 open BEGIN+DML fixture and exit 0 JSON `open_dml_groups` on its EOF prefix, real-parser duration ranking and `--large-trx-duration` alert on the MySQL 8.0.46 committed-duration fixture, cleanup, discovery/no-data behavior, workflows, release packing (README relative links must name a file the archive ships), and install.sh (sha256 verification that fails closed, readable download and flag errors); English golden output is pinned independently of the shell locale; real-parser per-transaction identity on mysql-8.0.46-flush-tables.binlog and minimal.binlog; real-parser busiest-minute driving tables on mysql-8.0.46-busiest-minute.binlog, where shop.catalog leads the window and shop.orders leads 14:05; real-parser replica apply delay on mysql-8.0.46-replica-apply.binlog matched to the mysqlbinlog commit-timestamp lines, a source file with equal timestamps, and `commit timestamps unavailable` on minimal.binlog and the MariaDB fixture; the MySQL 8.0 numeric decode matrix (`TestNumericDecodeMySQL80`, `-v` logs the checked value count) when `BINLOGVIZ_FLASHBACK_E2E=1`. |

## Exports

- `NewRootCommand() *cobra.Command` — Builds the full CLI root command tree.
- `ExitCode(err error) int` — Returns the process exit code for a command error (`2` for parsed-but-zero-events, otherwise `1`).
- `ExitError` — Command error carrying a non-default process exit code.
- `newAnalyzeCommand() *cobra.Command` — Defines analyze flags, including optional workload identity, exact single-file positions, complete-group GTID selectors, and snapshot persistence.
- `newCompareCommand() *cobra.Command` — Defines compare in both legacy file mode and snapshot mode.
- `newTrendCommand() *cobra.Command` — Defines trend in both explicit snapshot-list mode and pattern-selected snapshot mode, with optional baseline deltas.
- `newSnapshotCommand() *cobra.Command` — Defines the snapshot command subtree.
- `runAnalysisWithReportAndSnapshotOptions(...) error` — Executes analyze with optional snapshot metadata and snapshot persistence.
- `runAnalysisWithParserAndTempDirAndReportAndSnapshotOptions(...) error` — Test seam for command-path analyze behavior with explicit snapshot options.
- `createDuckDBTempStore(root string) (*detailstore.DuckDBStore, func() error, string, error)` — Creates a temp DuckDB file under a system or test-provided temp root and returns command-layer cleanup.

## Dependencies

- Upstream:
  - `internal/binlog` provides parser, progress-aware parsing, and normalization steps.
  - `internal/analyzer` provides streaming Consume/Finalize analysis. DuckDB is an optional CGO detail adapter via `NewWithStore`.
  - `internal/report` renders the final `AnalysisResult`.
  - `internal/compare` validates analyze JSON for compare workflows and renders compare output.
  - `internal/trend` validates ordered snapshot-backed trend inputs and renders multi-snapshot trend output.
- `internal/snapshot` resolves snapshot paths, persists named analyze JSON reports, and manages snapshot metadata/rename/delete operations.
- Downstream:
  - The compiled `binlogviz` CLI invokes this module as the user-facing entrypoint.

## Update Rule

If members, interfaces, discovery-mode behavior, or dependencies change, update this file in the same change.

## Notes

- Stage 3 keeps CLI semantics stable while moving the command execution path to true streaming consumption with command-owned DuckDB lifecycle.
- Stage 4 adds `--sql-context summary|off|full`; CLI parses the mode and delegates presentation decisions to `internal/report`. Report v3 records the selected mode and source-SQL availability without affecting provenance.
- Stage 5 adds command-path benchmarks for real fixture parsing and synthetic high-volume streaming workloads, keeps fixture assets under `internal/binlog/testdata`, and adds aggregate parse progress based on ordered input file sizes.
- `workflow_clean_snapdir_test.go` pins clean's snapshot-dir trust (`--snapshot-dir` or the default; 6 `snapshot_dir_mismatch`), relative `snapshot_dir` in exports, step-matched snapshot ledger entries, the two-sided preflight, and the exit-8 cause. `deletion_guard_test.go` flags every file-removing reference (aliases, `os.Root` methods, `os/exec`) in `cmd/binlogviz`, `internal/workflow` and `internal/snapshot` outside a reviewed allowlist, with mutant self-tests.
- `workflow_artifact_version_test.go` pins ADR 0010's consumer rule for workflow artifacts: a compare or trend JSON artifact with `schema_version` 99, 0 or `"1"` makes `workflow status`, `resume` and `clean` (preview and `--apply --force`) exit 9 `unsupported_artifact_version` with empty stdout and the artifact untouched; `schema_version` 1 and no key still work.

- `readme_shape_test.go` keeps `README.md` and `README_ZH.md` concise by allowlist: at most 360 lines and 16000 bytes, every ``` and ~~~ fence closed (fences only count at three spaces of indent or less, as GitHub renders them), no paragraph (soft-wrapped lines joined) or code line over 450 characters, each file's `##` (and setext `---` / `<h2>`) headings equal a fixed list, other heading levels may not announce a release or changelog, and no release-shaped token — the same `vX.Y`/`vX.Y.Z`/`X.Y.Z` rule the landing guard and release-check share, decoded from entities and fullwidth forms — outside install-command lines (`install.sh` with a flag, `releases/download/`, `go install`, `brew install`) and the allowed tokens (`readmeAllowedVersions`: Go toolchain, MySQL server; two-part numbers like `Apache 2.0` and addresses like `10.0.0.1` never count). `TestReadmeShapeCatchesBypassProbes` appends each BinlogQA bypass probe to the README and expects the named failure. The error names where release notes (`docs/releases/`, `CHANGELOG.md`) and behavior detail (`docs/reference/`, `docs/recipe/`) belong. `flashback_followup_test.go` reads the exit-code, trend-order, and apply-grant rules from the README together with `docs/reference/analyze-behavior*.md`, `docs/recipe/flashback*.md`, and `docs/recipe/compare-trend-workflow*.md`. `release_archive_test.go` additionally requires every relative link inside a shipped Markdown file to resolve to a file the archive packs, so offline docs never 404.

- Stage 8 adds named snapshot persistence under `~/.binlogviz/snapshots`, snapshot management commands, and snapshot-based compare input resolution while preserving legacy file-based compare.
- The trend command adds a higher-level historical workflow on top of the snapshot store. Explicit snapshot lists and workflow jobs keep CLI/plan order by default (`--order cli`); `--order time` sorts by `snapshot.window.start_time` and writes a stderr notice when it reorders.
- The snapshot subtree now supports long-lived snapshot management with rename/delete and JSON output for list/show so external tooling can consume the snapshot store without parsing text output.
- Compare legacy file mode accepts two JSON report paths only and rejects non-JSON positional inputs with one actionable error; snapshot mode remains available through paired flags.
- Discovery mode resolves ordered binlog files before entering the existing analysis pipeline, narrows `--from-dir/--prefix` inputs with `--start/--end` using file modification times plus one adjacent file on each bounded side for transaction-boundary evidence, and keeps the resolved list on `stderr` so report output on `stdout` stays machine-consumable. Those context files cannot add out-of-window workload totals. `--prefix mysql-bin` accepts an optional `.` before the numeric suffix so it matches `mysql-bin.000008`. A complete filename as `--prefix` selects that file; no-match errors that look like a filename hint `--prefix mysql-bin.` or `binlogviz analyze DIR/file` instead of repeating the same prefix.
- Analyze, compare, trend, snapshot, and workflow failure paths print the error once and do not dump full Usage. The process erases an in-progress stderr progress line before `Error:`, so the two never share a terminal line. Empty/truncated/corrupt files, including a short read the parser treats as EOF, use DBA-facing messages and exit 1. A complete binlog with zero counted events (empty time window, or Format Description / rotate only) exits 2 with empty stdout and one `Error:` line. HTML save confirmation goes to `stderr` only when a file was written. `analyze --format html` without `--output` writes a derived cwd file on a TTY and the HTML document to stdout when stdout is redirected. STATEMENT analyze (Query-DML with zero ROW images) exits 1 with empty stdout; the process prints the STATEMENT/MIXED sentence once as `Error:` and no report is written. MIXED files that still have ROW images exit 0 and still write a report. Successful MIXED JSON appends `alerts` `{type: input_format, severity: warning}` with counted ROW images and ignored Query-DML; `warnings` stays the truncated-query integer. `compare`, `trend`, `snapshot save` / `list` / `show` / `rename` / `delete`, and the workflow command tree (`run`, `resume`, `validate`, `describe`, `status`, `clean`, `export`) set `SilenceUsage` and `SilenceErrors` so the process is the single `Error:` printer.
- Active schema/object filters define the analyzed workload across summaries and report sections. A filter that leaves no row activity and no view, event, routine, or trigger DDL exits 2 without writing a success report, and the `Error:` line says the filter matched no events. A matching view, event, function, procedure, or trigger exits 0 and prints that DDL. `--include-table` / `--exclude-table` accept `TABLE` or `SCHEMA.TABLE` for tables and for those object names. `--snapshot-name` with any format other than `json` fails before a report is written.
- `--workload-id` is the operator's explicit positive workload identity and is persisted only as report evidence; its help follows runtime localization, and compare/trend never infer identity from server, schema, filename, version, or flavor metadata.
- Command temp-store cleanup remains directory-scoped and no longer depends on any SQL-context sidecar file; bounded SQL context now lives entirely inside the analyzer's DuckDB temp DB. Workflow analyze uses the same default `--detail-store none` path as the analyze command; DuckDB is created only when that mode is requested and CGO is enabled.
- Analyze keeps complete table data for JSON; `--top` / `--top-tables` limit only human report sections after totals are known, explicit `--top-tables=0` is unlimited, and `--top-transactions=0` emits all transaction aggregates.
- Analyze text output is now diagnostic-first by default: summary, top findings, top tables, and next actions are shown on stdout, while minute-level and write-shape detail are reserved for explicit detail controls in the report layer.
- Same-second ROW fixtures (duration `< 1s` with transactions) print operator-facing text TPS as `N/A (sub-second)` so `TxnCount/60` does not look like a parse failure; JSON `tps_series` stays numeric.
- `--top N` sets the default ranked output size for productized text and HTML report sections.
- `--detail-store none|duckdb` controls optional transaction detail persistence. The default `none` generates reports from streaming aggregates without DuckDB; `duckdb` keeps the detail backend enabled for future lookup workflows.
- `--details`, `--show-minutes`, and `--show-patterns` expand the default concise text report without changing analyzer semantics.
- `analyze --help` states that binlog timestamps are UTC, that explicit RFC3339 offsets define the filter instant, and that a zoneless `YYYY-MM-DD HH:MM:SS` is read in the `--tz` zone when `--tz` is set, including `--tz UTC`, and in the machine-local timezone when `--tz` is not set; inclusive-window comparison and UTC report display are unchanged.
- Analyze performance coverage includes text-vs-HTML rendering, corpus-backed DBA incident workloads, a CI-safe near-1GB synthetic mix benchmark, and an external real-binlog benchmark (`BenchmarkAnalyzeExternalRealBinlog`) gated behind `BINLOGVIZ_REAL_BINLOG` env var; real-fixture parser benchmarks isolate parse-only, parse+normalize, and end-to-end layers to identify per-stage bottlenecks.
- HTML report section IDs were consolidated from 7 flat sections to 5 semantic groups: `executive-summary`, `section-findings`, `section-activity`, `section-objects`, `section-evidence`. Product tests assert these IDs directly.
- `cmd/binlogviz/testdata/sql-corpus` now carries richer DBA-facing incident scenarios, including runner-up large/long/wide transactions so product tests can catch over-crowded transaction-evidence rendering instead of only toy single-winner cases. Corpus and mock parser events use canonical kinds (`QUERY`, `WRITE_ROWS`, `XID`, …), not go-mysql `String()` names.
- The production analyze command uses a destination-reuse normalization fast path in its streaming handler so the main CLI path no longer allocates one `*NormalizedEvent` per kept event.
- Multi-file analyze now overlaps parser work across files with bounded per-file buffers, but still feeds normalized events to the analyzer in input order so cross-file transactions remain valid.
- Analyze carries physical sizes for selected positional or discovered files into reports; counted event bytes remain a separate filtered row/DDL metric.
- `--start-position` / `--stop-position` use exact half-open event boundaries on one explicit file and intersect with `--start` / `--end`; mid-event, out-of-range, reversed, discovery, and multi-file position requests fail before rendering.
- `--include-gtids` / `--exclude-gtids` select complete transaction groups across ordered rotations. MySQL UUID ranges and exact MariaDB identities are canonicalized, exclude wins, unresolved or conflicting flavors fail, and valid no-match selections exit 2 without a report.
