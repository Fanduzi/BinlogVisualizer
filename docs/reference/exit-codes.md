# Exit codes and JSON errors

Every command maps a failure to one **kind**. The exit code is a function of the kind (ADR 0008, ADR 0009). Every error a command returns has a kind; a test fails the build on an untyped one (#277). The kind string is stable and does not change with `--lang`.

| Exit | Kind | When |
|---|---|---|
| 0 | | success |
| 1 | `error` | any failure with no other kind, including an open `BEGIN` or an unclassified QUERY that analyze cannot count safely (ADR 0001) |
| 2 | `no_data` | a complete binlog with nothing in range or nothing matching the filters (ADR 0001) |
| 3 | `usage` | unknown command, subcommand (`snapshot x`, `workflow x`) or flag, wrong arguments, an invalid `--format` (#251), `--error-format`, `--diagnostics` (including an explicit empty value), `--tz` (unknown, empty, or `Local`), `--start`/`--end`, GTID set, `--dml`, `--conflict`, `--where` or `--output` value, a negative count such as `--top-transactions -1` (#268), a missing required flag such as `snapshot save` without `--name`, an empty `--error-format=`, a bad `workflow resume --rerun` selector, an invalid snapshot name, a position selector that is out of range or not on an event boundary (#277), an unknown `schema` name |
| 4 | `input` | an input file or `--from-dir` is missing, unreadable or a directory, a `compare` report cannot be read, or `--schema-file` cannot be read (#268); a snapshot, snapshot source, workflow manifest or plan cannot be found or read, including a mode-000 snapshot (#277). Only a failed read: a manifest that does not decode is 5 |
| 5 | `corrupt` | not a binlog, empty (a 0-byte file, `/dev/null` and empty stdin alike, including an empty file passed to `flashback verify`), truncated, JSON or YAML that does not decode, or a report, snapshot, workflow plan or manifest missing required fields (`{}` included; a `{}` manifest is not legacy), a `diagnostics_mode` that is not a string (for example `1`; JSON `null` is absent, not corrupt), a workflow plan that fails validation (`details.reason: invalid_plan`), a manifest without `workflow_name` (`{}` included) in `workflow clean` or `export` (`details.reason: untrusted_manifest`), a corrupt event (including a CRC32 checksum mismatch), or no Format Description |
| 6 | `refused` | flashback cannot write an exact script: DDL in range, a row image that is not FULL, a `--schema-file` mismatch, `--sql-context off`. `redo` refuses with `details.reason` `capture`, `column_type`, `names`, `schema`, `generated_unknown`, `where_column` (ADR 0024), or `truncated_query` (ADR 0022), plus `details.table` when it names one table, and writes nothing to stdout; `flashback` uses the same `where_column` reason when `--where` names a column the row does not have. `binlogviz flashback verify` (ADR 0013) refuses with `details.reason` `not_flashback`, `truncated`, `missing_trailer`, `appended`, or `digest_mismatch`, and writes nothing to stdout. `workflow resume` refuses with `details.reason`: `plan_changed` (plan.yaml changed since the run; start a fresh run) or `trust_boundary` (the manifest's `plan_path` is outside the workflow root or not `<root>/plan.yaml`). `workflow clean` (preview and `--apply`) refuses and deletes nothing with `details.reason`: `untrusted_manifest` (no steps recorded while artifacts exist), `run_not_successful` (the latest run did not succeed; `--force` does not override) `no_ledger` (no `ledger.jsonl`, from an older binlogviz; re-run `workflow run` to rebuild it, or pass `--force`), `snapshot_dir_mismatch` (with `--include-snapshots`, the manifest's `snapshot_dir` is not the dir from `--snapshot-dir` or the default; `--force` does not override), or `trust_boundary` (`analyze/`, `compare/` or `trend/` is a symlink or leaves the root; `--force` does not override). A ledger entry with an absolute, `..` or otherwise malformed path is 5 with `untrusted_ledger`. `workflow run`, `resume` and `clean` refuse with `locked` while another of them holds `<root>/.lock`. See ADR 0009 §8. `workflow status` and `export` are read-only and still exit 0 on an out-of-root `plan_path`; export then warns on stderr and reports `plan_included: false` |
| 7 | `conflict` | flashback: a selected row was changed again later in the scanned binlogs (`--conflict refuse`, the default; #259) |
| 8 | `output` | writing the report, the script or the flashback temp file failed (for example ENOSPC). SIGPIPE stays 141 |
| 9 | `unsupported` | format and version limits only: a STATEMENT or MIXED binlog with no ROW images, a statement-format DML event in `redo` input (`details.reason: statement_format`, ADR 0022), a `report_version` newer than this build, a report trimmed by `analyze --diagnostics summary|off` given to compare, trend, or `snapshot save` (`details.reason: reduced_diagnostics`), a workflow plan version, or a legacy or newer `manifest_version`, this build cannot run or resume (#277). Valid JSON missing required fields is 5, not 9 |
| 10 | `resource` | flashback or redo hit an enforced ceiling (#317, ADR 0012, ADR 0013, ADR 0022). `details.reason` is `spill_limit` when `BINLOGVIZ_SPILL_BYTES` is a positive byte count and the row spill plus the generated-column review spill grow past it, or `memory_limit` when `HeapAlloc` stays above 90% of `BINLOGVIZ_MEMORY_BYTES` (or of `GOMEMLIMIT` when that variable is unset) after one GC. `flashback verify` uses that same heap ceiling (#327) and does not buffer the script. Unset `BINLOGVIZ_SPILL_BYTES` means no byte ceiling. A set value that is not a positive base-10 integer (`abc`, `0`, `-1`, `1MB`, empty) is exit 3 before a binlog is read. `BINLOGVIZ_MEMORY_BYTES` uses the same rule. A full disk (ENOSPC) stays 8, including a full disk while verify copies a script to its temp file. Analyze and flashback with `--include-gtids`/`--exclude-gtids` also exit 10, `details.reason` `matched_gtid_intervals` with `limit` and `intervals`, when the matched GTIDs leave more than 100,000 separate intervals in `selection.matched_gtid_set` (#379); narrow the selectors or split the input. This is never 2: a runtime out-of-memory exit is not an empty result |
| 11 | `spill` | analyze could not read back the per-(table, minute) activity spill. That includes a read while finishing the analysis (the default store and `--detail-store duckdb`) and a read while rendering json, text, markdown, or html (ADR 0019). Stdout is empty. This is not a generic failure (exit 1) and not an output write failure (exit 8): the report was never written. A spill file that cannot be created or written is not this code; that series stays in memory and the run continues |

Signals keep their shell codes: SIGHUP 129, SIGINT 130, SIGQUIT 131, SIGTERM 143.

## JSON errors

`--error-format json` (any command), or `BINLOGVIZ_ERROR_FORMAT=json` in the environment, replaces the `Error:` line with one JSON object on stderr. `--error-format` takes `text` or `json`; any other value is a usage error. With JSON errors that object is the only line a failed run writes to stderr: no usage text and no info lines (#268). Warnings still print. Under JSON errors, `workflow export`'s plan warning is also one JSON line: `{"warning":{"code":"plan_not_included","message":"…"}}`.

```json
{"error":{"kind":"corrupt","code":5,"message":"parse error: corrupt event, type 31, ending at position 500, size 45: invalid table id 0","details":{"event_type":31,"end_position":500,"event_size":45,"cause":"invalid table id 0"}}}
```

- `kind` and `code` are stable; `message` is localized.
- `details` is present only when there is something machine-readable: a `reason` (`invalid_plan`, `plan_changed`, `trust_boundary`, `untrusted_manifest`, `run_not_successful`, `no_ledger`, `untrusted_ledger`, `locked`, `snapshot_dir_mismatch`, `spill_limit`, `memory_limit`); a corrupt event's `event_type`, `end_position`, `event_size` and `cause`; a flashback conflict's `count` and `listed` (table, key, later GTID and position).
- A corrupt event never prints the parser's Go struct or raw event bytes (#254).

## Progress and quiet mode

The progress bar, carriage returns and ANSI erase codes are written only when stderr is a terminal and `TERM` is not `dumb`. A pipe or file gets one plain `Finalizing analysis...` line. `--quiet` (`-q`, any command) drops progress and info lines (resolved paths, save confirmations); errors and warnings still print (#253). JSON errors drop the info lines too (#268). An unknown command prints the error only, not the usage text; run `--help` for that.
