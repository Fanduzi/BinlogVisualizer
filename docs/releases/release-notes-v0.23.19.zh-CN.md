# BinlogViz v0.23.19 发布说明

发布日期：2026-10-07

## 概述

v0.23.19 在 DDL 时间线上点名每条 DDL 所在的事务，DBA 不用再去 binlog 里搜就能复制停止位点。binlog 里有 GTID 时，时间线写出这个 GTID、事务开始的文件和字节，以及可直接复制的 `mysqlbinlog --stop-position`（MariaDB 写成 `mariadb-binlog`）。有 GTID 时还会写出 `BinlogServer stop_gtid`。这个停止位点会回放更早的事件，并且不包含这条 DDL。在 `mysql-8.0.46-drop-table.binlog` 上，`DROP TABLE shop.orders` 的 GTID 是 `4d8275bc-c221-11f1-a25e-822b383dbcd0:2`。GTID 事件从字节 523 开始。Query 事件仍是 600–734。没有新的 CLI 参数。本版本是 #144。与 BinlogServer v0.5.54 的 `stop_gtid` 配套。

## 新功能

- **DDL 时间线点名事务所在位置，并给出不含这条 DDL 的停止位点（#144）**：`binlogviz analyze` 在文本、Markdown、HTML 的每条 DDL 时间线下面加上这个身份。文本标题仍是 `=== DDL 时间线 ===`。原有的操作行下面，一行身份只在 DDL 事件记下了它们时写出 `server_id=`、`thread_id=` 和 `user@host=`，然后是 `gtid=` 或 `GTID 不可用`。后面几行是 `事务起点 <file>:<byte>`、`停在这条 DDL 之前（回放更早的事件，不包含这条 DDL）`、`mysqlbinlog --stop-position=<N> <file>`，有 GTID 时还有 `BinlogServer stop_gtid=<gtid>`。`<N>` 是该事务开始的字节。有 GTID 事件时，这个字节是 GTID 事件的起点（`# at`），不是 Query 事件，也不是 `end_log_pos`。`position_start` 和 `position_end` 仍是 Query 事件。在 `mysql-8.0.46-drop-table.binlog` 上，这条 DROP 写出 `server_id=1 thread_id=8 gtid=4d8275bc-c221-11f1-a25e-822b383dbcd0:2`、`事务起点 <file>:523`、`mysqlbinlog --stop-position=523 <file>`，以及 `BinlogServer stop_gtid=4d8275bc-c221-11f1-a25e-822b383dbcd0:2`。Query 事件是 `position_start` 600、`position_end` 734。这份 fixture 没有记下调用方，所以不写 `user@host`。`mysqlbinlog --stop-position=523` 保留更早的 `before-drop` 插入，排除 `DROP TABLE` 和之后的 `after-drop` 插入。JSON 在 `diagnostics.ddl_events[]` 上增加：`gtid`（MySQL `uuid:seq` 或 MariaDB `domain-server-seq`）、`txn_start_file`、`txn_start_pos`、`server_id`、`thread_id`、`actor`（`user` / `host`）、`mysqlbinlog_stop`、`stop_gtid`（同一个 GTID，给 BinlogServer 的 `stop_gtid`），以及 `stop_note`。缺的值省略。不会写成空字符串，也不会写成 `0`。MariaDB 的服务器版本在 `mysqlbinlog_stop` 里用 `mariadb-binlog`。标准输入没有文件路径，所以省略 `mysqlbinlog_stop`。`--sql-context off` 仍会丢掉语句（`DROP TABLE … generated by server` 不再出现），GTID、位点和停止提示都留下。没有新的参数。
- **GTID 关闭和匿名 GTID 不点名（#144）**：`minimal.binlog` 写出 `GTID 不可用`，不写 `gtid=`，也不写 `BinlogServer`，仍然写出 `mysqlbinlog --stop-position=`。JSON 省略 `gtid` 和 `stop_gtid`，并把 `gtid_note` 设为 `GTID unavailable`（`--lang zh-CN` 时是 `GTID 不可用`）。binlog 里没有 GTID 事件时，`txn_start_pos` 就是 Query 事件的 `position_start`。匿名 GTID 事件同样省略 GTID，`txn_start_pos` 是那个 GTID 事件的起点，不是 Query 事件。

## 兼容性说明

- 默认文本、Markdown、HTML 的 DDL 时间线条目会变长，多出身份行、事务起点和停止命令。没有 DDL 的文件不变。JSON 在 `diagnostics.ddl_events[]` 上增加上面这些字段。`position_start` 和 `position_end` 仍是 Query 事件。
- `--sql-context off` 在每种格式里仍省略语句。GTID、位点和停止提示都留下。
- `--include-table`、`--exclude-table`、schema 过滤，以及时间、位点、GTID 过滤，仍决定列出哪些 DDL。身份是留下的那条 DDL 所在的事务。
- 没有新的 CLI 参数。退出码 0 / 1 / 2 仍按 ADR-0001。
- MariaDB 服务器版本写出 `mariadb-binlog`，而不是 `mysqlbinlog`。标准输入省略 `mysqlbinlog_stop`。
- 快照、工作流、产物命名和支持平台除此之外与 v0.23.18 一致。
- workflow、trend、compare 与 snapshot 行为不变。本版本不生成回滚或 flashback SQL。
