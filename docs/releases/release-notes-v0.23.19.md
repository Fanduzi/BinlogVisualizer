# BinlogViz v0.23.19 Release Notes

Release date: 2026-10-07

## Overview

v0.23.19 names, on the DDL Timeline, the transaction that holds each DDL, so a DBA can copy a stop without grepping the binlog. The timeline prints that GTID when the binlog has one, the file and byte where the transaction starts, and a copy-ready `mysqlbinlog --stop-position` (MariaDB prints `mariadb-binlog`). When a GTID exists it also prints `BinlogServer stop_gtid`. That stop replays earlier events and excludes this DDL. On `mysql-8.0.46-drop-table.binlog`, `DROP TABLE shop.orders` is GTID `4d8275bc-c221-11f1-a25e-822b383dbcd0:2`. The GTID event starts at byte 523. The Query event stays 600–734. There is no new CLI flag. This is #144. It pairs with BinlogServer v0.5.54 `stop_gtid`.

## New Features

- **DDL Timeline names the transaction and a stop that excludes it (#144)**: `binlogviz analyze` adds that identity under each DDL Timeline entry in text, Markdown, and HTML. The text heading stays `=== DDL Timeline ===`. Under the existing operation line, one identity line prints `server_id=`, `thread_id=`, and `user@host=` only when the DDL event recorded them, then `gtid=` or `GTID unavailable`. The next lines are `txn start <file>:<byte>`, `stop before this DDL (replays earlier events, excludes this DDL)`, `mysqlbinlog --stop-position=<N> <file>`, and, when a GTID exists, `BinlogServer stop_gtid=<gtid>`. `<N>` is where that transaction starts. With a GTID event, that byte is the GTID event's start (`# at`), not the Query event and not `end_log_pos`. `position_start` and `position_end` stay the Query event. On `mysql-8.0.46-drop-table.binlog` the DROP prints `server_id=1 thread_id=8 gtid=4d8275bc-c221-11f1-a25e-822b383dbcd0:2`, `txn start <file>:523`, `mysqlbinlog --stop-position=523 <file>`, and `BinlogServer stop_gtid=4d8275bc-c221-11f1-a25e-822b383dbcd0:2`. The Query event is `position_start` 600 and `position_end` 734. That fixture records no invoker, so it does not print `user@host`. `mysqlbinlog --stop-position=523` keeps the earlier insert of `before-drop` and excludes `DROP TABLE` and the later insert of `after-drop`. JSON adds, on `diagnostics.ddl_events[]`: `gtid` (MySQL `uuid:seq` or MariaDB `domain-server-seq`), `txn_start_file`, `txn_start_pos`, `server_id`, `thread_id`, `actor` (`user` / `host`), `mysqlbinlog_stop`, `stop_gtid` (the same GTID, for BinlogServer `stop_gtid`), and `stop_note`. A missing value is omitted. It is never an empty string and never `0`. MariaDB server versions use `mariadb-binlog` in `mysqlbinlog_stop`. Stdin has no file path, so `mysqlbinlog_stop` is omitted. `--sql-context off` still drops the statement (`DROP TABLE … generated by server` is gone) and keeps the GTID, the positions, and the stop hint. There is no new flag.
- **GTID off and an anonymous GTID stay unnamed (#144)**: `minimal.binlog` prints `GTID unavailable`, does not print `gtid=` or `BinlogServer`, and still prints `mysqlbinlog --stop-position=`. JSON omits `gtid` and `stop_gtid` and sets `gtid_note` to `GTID unavailable`. When the binlog has no GTID event, `txn_start_pos` is the Query event's `position_start`. An anonymous GTID event is the same omission, and `txn_start_pos` is that GTID event's start, not the Query event.

## Compatibility

- Default text, Markdown, and HTML DDL Timeline entries grow by the identity line, the transaction-start byte, and the stop commands. A file with no DDL is unchanged. JSON adds the fields above on `diagnostics.ddl_events[]`. `position_start` and `position_end` stay the Query event.
- `--sql-context off` still omits the statement in every format. The GTID, the positions, and the stop hint stay.
- `--include-table`, `--exclude-table`, schema filters, and time, position, and GTID filters still decide which DDL is listed. The identity is the transaction that holds the DDL that remains.
- There is no new CLI flag. Exit codes 0, 1, and 2 keep ADR-0001 meaning.
- A MariaDB server version prints `mariadb-binlog` instead of `mysqlbinlog`. Stdin omits `mysqlbinlog_stop`.
- Snapshots, workflows, artifact names, and supported platforms are otherwise unchanged from v0.23.18.
- Workflow, trend, compare, and snapshot behavior are unchanged. This release does not emit rollback or flashback SQL.
