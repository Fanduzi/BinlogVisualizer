# BinlogViz v0.23.26 发布说明

发布日期：2026-10-09

## 概述

v0.23.26 让 `binlogviz flashback` 守卫报错里保留非 ASCII 列名（#192）。MySQL 把 `ERROR 1231` 的值截到 200 字节。守卫原来按字符挑整个列名，中文列名的列表会超过 200 字节，报错就退回只显示列数。现在按字节挑列名。守卫拒绝的情况不变，仍然不写入任何行。`analyze` 的输出和其他 flashback 语句与 v0.23.25 相同。

## 变更

- **守卫报错按字节列出列名（#192）**：守卫 SQL 用 `200 - LENGTH(head)` 作为余量，在列表的二进制副本上挑整个列名，再从原列表取同样多的字符。分隔符 ` | ` 是 ASCII，所以截断总落在字符边界上。值是合法 UTF-8 且不超过 200 字节，在 MySQL 8.0 和 5.7 上都能完整到达客户端。
- 一个完整列名都放不下时，值是只有列数的形式，例如 `(1 columns)`，末尾不带 `: `。
- 完整列表仍由守卫的 `SELECT` 打印到 stdout。

## Bug 修复

- #192：列名是非 ASCII 时，`ERROR 1231` 那一行只显示列数、没有列名，而 200 字节其实放得下好几个。#192 的复现（六个 `生成列_客户全名_N` 列）现在列出 4 个名字，共 199 字节。

## 验证

- 合并提交上的 CI、`go test ./...`，以及在全新 MySQL 8.0.46 上跑的 MySQL 8.0 端到端测试（含 `TestFlashbackRoundTripMySQL80`）：通过。
- 在 MySQL 8.0.46 和 5.7.44 上跑 20 个真实的守卫报错用例（中文、Latin-1、ASCII 和混合列名；恰好 199、200、201 字节的列表；跨截断点的字符；单个 64 字符中文列名；跨表 40 和 60 列；含 `,` 和 ` | ` 的列名），用 `mysql --force` 和遇错继续的执行器：两台服务器上 20/20 与预期一致。80 次执行都写入 0 行，GTID 集合不变。v0.23.25 在其中 10 个用例里只显示列数。
- 对截断 SQL 做模糊测试（1 到 4 字节的列名，1–80 个列名）：除下面的 #208 外，每台服务器 3000 个用例 0 个不一致。
- 目标不对：每台服务器 21/21 安全，覆盖 `mysql`、`--force`、`source`、终端粘贴、`mysqlsh`、遇错继续的执行器、不带脚本头的块、残留或伪造的守卫状态、XA 和重连。目标正确：每台服务器 6/6 还原一致。
- 正确执行：生成的脚本与 v0.23.25 相比，只有守卫截断行和每个脚本的令牌不同。570 个用例的离线 flashback 差异对比没有实际差异，拒绝情况不变。`analyze` 在 1473 个用例上与 v0.23.25 逐字节一致。

## 破坏性变更

无。守卫报错里现在可能出现 v0.23.25 用列数代替的列名。

## 兼容性说明

- 执行支持 MySQL 5.7 及以上、MariaDB 10.2 及以上。
- `flashback` 从不连接 MySQL。先审阅、测试脚本，再在主库上新开一个会话、`sql_log_bin=1`、带上脚本头执行。某条语句失败时，脚本里更早的事务已经提交。
- JSON `report_version` 仍是 `3`。快照、工作流、产物名和支持的平台与 v0.23.25 相同。

## 已知问题

完整说明和绕过办法见 `docs/concept/limitations.zh-CN.md`。

- 目标正确时，块中间重连会让这个块没有应用。在新会话里带上脚本头，从这个块接着执行。
- [#167](https://github.com/Fanduzi/BinlogVisualizer/issues/167)：解析到的 binlog 里的 `ALTER` 会再应用到已经包含它的转储上。拼接的多库转储只用第一个 `Database:` 头。
- [#187](https://github.com/Fanduzi/BinlogVisualizer/issues/187)、[#193](https://github.com/Fanduzi/BinlogVisualizer/issues/193)：带空格的 `Database:` 头和 `lower_case_table_names` 下的大小写混用；非默认 `div_precision_increment` 加 `DECIMAL` 操作数。都会安全失败。
- [#208](https://github.com/Fanduzi/BinlogVisualizer/issues/208)（P2）：以 ` |` 结尾的列名在 `ERROR 1231` 那一行里可能被从中间截断，显示一个不存在的列名。只影响可读性，仍会安全失败：守卫照样拒绝，会话被锁定，写入 0 行，stdout 上的 `SELECT` 有完整列表。
- 脚本不知道的生成列（没有 `--schema-file`，解析到的 binlog 里也没有 `CREATE`）仍会被赋值，执行可能停在 `ERROR 3105`。
- 执行失败后接着跑：保留脚本头（第一个 `-- gtid:` 之前的所有行），只删掉失败块上面的块，在新会话里执行脚本头加上失败块及其后的全部内容。
