# ADR 0009: Every command error has a kind

Status: accepted (2026-10-16). Tracks #277. Extends ADR 0008 §4.

## Context

ADR 0008 introduced `internal/clierr` and exit codes 3–8, but only a few commands used it. The v0.24.0 review (BinlogQA, 2026-10-16) counted about 149 plain `fmt.Errorf`/`errors.New` sites in `cmd/binlogviz`, and only 7 files used `clierr`. So exit 1 still covered too much:

- `snapshot save` without `--name` exited 1 (cobra's untyped required-flag error).
- A snapshot source that is not valid JSON exited 1.
- A STATEMENT or MIXED binlog with no ROW images exited 1.
- `analyze /dev/null` exited 4 (input) and `analyze empty.binlog` exited 5 (corrupt), for the same failure.

An agent cannot tell "fix your arguments" from "this file is bad" from "this tool cannot read this format" without scraping localized text.

## Decision

1. **One new kind.** `unsupported`, exit 9, is reserved for **format and version limits** of this build: intact, well-formed input in a format or version binlogviz does not handle. Today that means:
   - a binlog whose DML is only in STATEMENT form (no ROW images);
   - a report whose `report_version` is newer than this build supports;
   - a workflow plan version, or a real manifest version marker, that this build cannot run or resume: `manifest_version` newer than 2, or a legacy manifest (no `manifest_version` but legacy content such as `workflow_name`). A manifest with none of its fields (`{}`) is `corrupt` (5), not legacy;
   - a plan option that v1 does not support (`defaults.analyze.format` other than json).

   It differs from `corrupt` (5): the file is fine, and the fix is a different binlog format, tool or binlogviz version. Retrying the same input with this build will not help. Valid JSON that lacks required fields (for example `{}` given as a report or snapshot) is **not** 9: that is content that is broken for its purpose, so it is `corrupt` (5).
2. **Rule for choosing a kind.**
   - `usage` (3): the fix is in the command line: a flag, argument, name or format value, including a missing required flag and a value that is out of range for the given input.
   - `input` (4): an input the user named cannot be found, opened or read (file, directory, snapshot, manifest, plan). Only the read itself: a manifest that reads but does not decode is 5.
   - `corrupt` (5): an input was read but its content is broken: not a binlog, empty (a 0-byte file, `/dev/null` and empty stdin alike), truncated, JSON or YAML that does not decode, or a report, snapshot, workflow plan or manifest that decodes but lacks required fields or has invalid values. The message says so ("corrupt BinlogViz report: missing required fields"). A workflow plan that fails validation carries `details.reason: "invalid_plan"`, so an agent can tell an authoring mistake from file damage.
   - `refused` (6): the input is readable and well-formed, and binlogviz deliberately refuses to act on it to protect correctness. Beyond flashback (ADR 0008), `workflow resume` refuses with `details.reason`: `plan_changed` when plan.yaml no longer matches the manifest's `plan_sha256` (the fix is a fresh run), and `trust_boundary` when the manifest's `plan_path` resolves outside the workflow root or is not `<root>/plan.yaml`.
   - `unsupported` (9): above.
   - `output` (8): writing a report, artifact, temp file or manifest failed.
   - `error` (1): only failures that have no better kind, chiefly ADR 0001's open BEGIN and unclassified QUERY, and internal invariants.
3. **Every error is built typed.** In `cmd/binlogviz` and in the packages whose errors a command returns as-is (`internal/snapshot`, `internal/workflow`, `internal/compare`, `internal/trend`), errors are created with `clierr.Errorf(kind, …)` or `clierr.New(kind, …)`, and bare OS and JSON errors are wrapped with `clierr.Wrap` where they are returned. `fmt.Errorf` and `errors.New` are allowed only for package-level sentinels. `TestNoUntypedErrors` parses all of these packages and fails on any other use. `internal/analyzer`, `internal/binlog` and `internal/report` errors reach the user only through `cmd/binlogviz`, which gives them a kind at that boundary. Bare `return err` of an OS error is not caught statically, so it is covered by command tests (for example a mode-000 snapshot exits 4).
4. **Innermost kind wins.** `clierr.Errorf` with a `%w` operand that already has a kind keeps that kind, like `clierr.Wrap`. Context added on the way up (`analyze window "w1": …`) never hides the specific classification.
5. **A flag set to an empty value is a usage error.** `--error-format=` exits 3; only an unset flag falls back to `BINLOGVIZ_ERROR_FORMAT` or text.
6. **Required flags are checked in `RunE`.** Cobra's `MarkFlagRequired` returns an untyped error before our code runs, so commands check required flags themselves and return `usage`.

7. **Read-only commands do not enforce resume policy.** `workflow status` and `workflow export` only read and report. On a `plan_path` outside the workflow root they still exit 0: `status` reports the run as not resumable, and `export` skips plan.yaml with a warning, printed on stderr as well as in the output, and `--format json` reports `"plan_included": false`. The trust boundary guards what `resume` executes, not what is displayed.
8. **Clean deletes only files the workflow provably wrote (#288, #289).** The manifest alone is not enough: it is rewritten by every run, including a failed one, so it describes the latest attempt, not what is on disk. Before this rule, a renamed window plus a failed re-run left a manifest with one failed step, and `clean --apply --include-snapshots` deleted the last good run's analyze outputs and snapshots with exit 0 (#289).
   - **Ledger.** Every `workflow run` and `resume` appends one line per file it wrote to `<output_dir>/ledger.jsonl`: `path` (always relative: `<analyze|compare|trend>/<file>` for artifacts, a bare `<name>.json` in the configured snapshot dir for snapshots, recorded by step `analyze:<name>`; any other step is `untrusted_ledger`), `kind` (`artifact` or `snapshot`), `step` (`analyze:week1`), `run_id` (also stored in the manifest), `sha256` and `written_at`. The ledger is append-only and is written before the manifest. Reused steps are not re-recorded. A snapshot is recorded only when a successful analyze step saved it. A failed ledger write is reported on stderr and only loses attribution, which makes clean keep more, never delete more.
   - **Gate, in order; preview and `--apply` give the same result:**
     1. The manifest integrity check: a manifest missing `workflow_name` (`{}`) is **5 corrupt**, and a manifest that records no steps while `analyze/`, `compare/` or `trend/` hold files is **6 refused**, both with `details.reason: untrusted_manifest`.
     2. The latest run's `status` must be `success`, else **6 refused**, `details.reason: run_not_successful`. `--force` does not override this: after a failed run nothing is deleted, snapshots included.
     3. A ledger must exist, else **6 refused**, `details.reason: no_ledger`, unless `--force`. A corrupt ledger line, or any entry whose path is absolute, contains `..`, a backslash or a hidden component, or does not have the shape above, is **5 corrupt**, `details.reason: untrusted_ledger`: the whole ledger is distrusted, nothing is deleted, `--force` or not.
     4. Each of `<root>/analyze`, `compare`, `trend` must be absent or a real directory (not a symlink) inside the real root, else **6 refused**, `details.reason: trust_boundary`, before anything is deleted and even with `--force`.
   - **Per-file attribution.** A file no current step owns is deleted only if the ledger records its path and its current sha256 matches a recorded hash: the workflow wrote exactly these bytes and a later run superseded them. Every other file is an orphan: manual files, files edited since, files of a step that never recorded them. Orphans are listed as `kept_orphans` and kept. `--force` also deletes unattributed `.json`/`.html` outputs, but only in a kind directory the manifest recorded a step for.
   - **Snapshots.** `--include-snapshots` deletes only snapshots the ledger attributes (path and hash) that no current successful analyze step owns. A snapshot the workflow did not create, for example one that merely shares the snapshot directory or a name, is never deleted, not even with `--force`.
   - **One deletion primitive (QA r5 on #290).** Every deletion goes through `workflow.TrashFile(root, rel, id)`. It rejects absolute paths and `..`, refuses a symlink at every component (`Lstat` per component, then a rename inside `os.Root`, which cannot leave the root), and requires a regular file. Artifacts are resolved against the real output root and snapshots against the configured snapshot dir, so `--force` can never reach beyond `<root>/{analyze,compare,trend}` or files directly inside the snapshot dir. A symlinked file in a kind dir is never a candidate; it is listed in `kept_orphans`. A guard test covers every non-test file in `cmd/binlogviz`, `internal/workflow` and `internal/snapshot`. It flags any reference, called or not, to a removing function on `os`, `syscall` or `x/sys/unix` (also through an import alias or a function value such as `rm := os.Remove`), any `Remove`/`RemoveAll`/`Rename` method (for example on `os.Root`), and any `os/exec` use. Every allowed site is listed in a reviewed allowlist with its reason, and stale entries fail too.
   - **The snapshot dir comes from the caller (QA r2 on #290).** `manifest.snapshot_dir` is a file in the workflow dir: it can be forged, or restored from an export made on another machine. With `--include-snapshots`, clean uses `--snapshot-dir` or the default snapshot dir, and if the manifest's value (resolved against the workflow root when relative) names a different directory it refuses with **6 refused**, `details.reason: snapshot_dir_mismatch`, before anything moves, even with `--force`. `workflow export` writes `snapshot_dir` as `"snapshots"`, relative to the archive root, so a restored copy can only ever point at its own `snapshots/`.
   - **Preflight.** `--apply` first runs every check on every target, artifacts and snapshots alike (path shape, no symlink at any component, regular file, trash dirs creatable and real directories). If any check fails, clean exits without moving anything (6 for a trust refusal, 8 for an unusable trash, with the path and the cause in the message). A move that still fails afterwards (for example `EXDEV` across filesystems) is listed in `skipped` with `skip_reasons`, and the exit-8 message names each file and why.
   - **Trash, not unlink.** `--apply` moves files to `<root>/.trash/<id>/` (snapshots to `<snapshot-dir>/.trash/<id>/`) with a same-filesystem rename, and reports `trash_dir` / `snapshot_trash_dir`. Clean never empties the trash; that is left to the user, so a wrong deletion is always recoverable.
   - **Lock.** `workflow run`, `resume` and `clean` take an exclusive non-blocking `flock` on `<root>/.lock`. A concurrent command exits **6 refused**, `details.reason: locked`, so clean cannot race a run that is still writing files and the ledger.
   - **Migration.** Workflow directories written before the ledger have none, so clean refuses with `no_ledger`. Re-running `binlogviz workflow run <plan.yaml>` into the directory rebuilds the ledger for every file that run writes. `--force` is the explicit opt-out, and it never deletes snapshots, because nothing proves they are ours.
   - **Why 6, not 5.** In all three refusals the inputs are readable and well-formed. Clean refuses on purpose because it cannot prove a deletion is safe, which is rule 2's `refused`. `untrusted_ledger` is 5 because that file's content is broken.
   - `workflow export` applies the integrity check: a `{}` manifest exits 5. For a manifest with no steps, export warns that artifacts on disk are not included. A plan.yaml left out of the archive is reported on stderr: as one JSON line, `{"warning":{"code":"plan_not_included","message":…}}`, under `--error-format json`, and as a text line otherwise. Export JSON also carries `plan_included`. The archive includes `ledger.jsonl`, so a restored directory can still be cleaned without `--force`.

## Consequences

- Scripts that matched exit 1 for these cases must read the new codes; the JSON error `kind` is the stable contract (`docs/reference/exit-codes.md`).
- ADR 0012 adds `resource`, exit 10, for an enforced flashback spill or memory ceiling. It is not a format limit (`unsupported`, 9) and not a full disk (`output`, 8). A Go runtime out-of-memory death is status 2 with no JSON; exit 10 exists so a ceiling the process can see is never reported as `no_data`.
- `analyze /dev/null` now exits 5 like an empty file.
- Position selectors that are out of range or not on an event boundary exit 3 (usage) instead of 1.
- Adding a new error without a kind fails CI.
